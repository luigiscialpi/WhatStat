# Ricalcolo risultati Analisi testi con possibilità di interruzione

## Obiettivo
Quando l'utente seleziona 20 risultati nella Dashboard o ChatDetail, se i dati cachati sono insufficienti (solo 10), avviare un ricalcolo con possibilità di annullamento.

### Pattern esistente (WordSearch)

- Bottone X nella UI durante ricerca

## Implementazione

### 1. DashboardViewModel

```kotlin
// Aggiungere variabili
private var slowStatsJob: Job? = null
private val _selectedLimit = MutableStateFlow(10)
val selectedLimit: StateFlow<Int> = _selectedLimit.asStateFlow()

// Nuova funzione per ricalcolo con limite superiore
fun recalculateWithLimit(limit: Int) {
    if (limit <= 10) {
        // Usa dati esistenti, basta aggiornare il limite
        _selectedLimit.value = limit
        return
    }
    
    // Ricalcola per limite > 10
    slowStatsJob?.cancel()
    slowStatsJob = viewModelScope.launch {
        _isLoadingSlow.value = true
        _loadingProgressSlow.value = 0
        try {
            val (startTime, endTime) = if (_selectedTimeRange.value == TimeRange.CUSTOM) {
                _customDateRange.value?.let { analyticsRepository.getDateRangeBounds(it) } 
                    ?: (null to null)
            } else {
                analyticsRepository.getTimeRangeBounds(_selectedTimeRange.value, _customDateRange.value)
            }
            
            // Richiedi più dati dal repository
            val slowStats = analyticsRepository.getSlowGlobalStats(
                startTime = startTime,
                endTime = endTime,
                onProgress = { progress -> _loadingProgressSlow.value = progress }
            )
            
            _globalStats.value = _globalStats.value?.copy(
                topWords = slowStats.topWords,
                topEmojis = slowStats.topEmojis,
                topStickers = slowStats.topStickers
            )
            _selectedLimit.value = limit
        } catch (e: CancellationException) {
            // Annullato
        } catch (e: Exception) {
            android.util.Log.w("WhatStat", "Recalculate failed: ${e.message}")
        } finally {
            _isLoadingSlow.value = false
            _loadingProgressSlow.value = null
        }
    }
}

fun cancelSlowStats() {
    slowStatsJob?.cancel()
    _isLoadingSlow.value = false
    _loadingProgressSlow.value = null
}
```

## Bug 2c: Cache non salvata per limit > 10

### Problema
- Se l'utente richiede 20 risultati e aspetta il ricalcolo, questi dati NON vengono salvati in cache
- Se poi seleziona 10 e poi di nuovo 20, il ricalcolo parte da capo

### Soluzione proposta
Nel ViewModel, dopo un ricalcolo con limite > 10:
1. Salvare in variabile `_cachedSlowStatsFull` i risultati completi
2. Quando si richiede un limite minore (20 → 10), usare `.take()` dai dati salvati
3. Quando si richiede un limite maggiore (10 → 20), usare prima i dati salvati se sufficienti

In pratica, modificare `setLimit()`:
```kotlin
fun setLimit(limit: Int) {
    if (limit == _selectedLimit.value) return
    
    // Se abbiamo già dati per un limite maggiore, usa quelli
    val cachedForHigher = _cachedSlowStatsFull
    if (cachedForHigher != null && limit <= 20) {
        // Usa i dati cachati con .take()
        _globalStats.value = _globalStats.value?.copy(
            topWords = cachedForHigher.topWords.take(limit),
            topEmojis = cachedForHigher.topEmojis.take(limit),
            topStickers = cachedForHigher.topStickers.take(limit)
        )
        _selectedLimit.value = limit
        return
    }
    
    // Altrimenti ricalcola se necessario
    if (limit > 10) {
        _selectedLimit.value = limit
        loadSlowStats()
    } else {
        _selectedLimit.value = limit
    }
}
```

E aggiornare `loadSlowStats()` per salvare i dati completi:
```kotlin
// Dopo aver ottenuto i risultati
val fullStats = GlobalStats(..., topWords = slowStats.topWords, ...)
_cachedSlowStatsFull = fullStats
```
